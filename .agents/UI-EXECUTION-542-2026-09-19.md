## Source-level diagnosis

Installed `@solidjs/vite-plugin` chooses server or DOM transforms for test mode
but defaults `hydratable` to `false`; its public `solid` options are merged
after that default. Explicit `solid: { hydratable: true }` is therefore the
smallest correct config fix and preserves environment-specific compilation.

Installed Solid 2 owns `sharedConfig` hydration state and schedules deferred
verification plus `_$HY.done`/registry work through a microtask and zero-delay
timer even when the fixture throws. The old helper reset those fields itself
and ended capture too early. The new helper marks a hydrate attempt before the
call, drains that bounded lifecycle on both success and hydrate-throw paths,
then restores console/global state. An independent caught-state flag preserves
falsy thrown values, while cleanup/barrier errors cannot replace a primary
failure. A successful call must return a callable disposer and install the
pinned runtime verifier; neither contract can silently certify a run.

Disclosure IDs require the SSR hydration context supplied by
`renderToString`, not `createRoot`. Meter's fallback role is intentionally a
two-token contract. The corrected tests preserve both facts.
