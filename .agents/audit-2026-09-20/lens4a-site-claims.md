## Verdict

### Would you ship an RC from this tree?

**No.** I would not ship a release candidate from this tree in its current state. 

The public documentation contains outright false claims about how the packages are architected and can be installed, alongside broken/stale installation instructions that will fail for every new user on Solid 2.

### Three things to fix first:

1. **Retract the false package re-export / stacking claim (`installation.tsx:77` in both installation pages)**:
   The claim that *"The five packages stack. Each one re-exports the layer beneath it, so install the highest one you need and nothing else — the lower layers come with it"* is completely FALSE. Neither `@proyecto-viviana/ui` nor `@proyecto-viviana/solid-spectrum` re-exports the lower layers (`solidaria-components`, `solidaria`, `solid-stately`) wholesale, and the two styled libraries are siblings, not stacked on top of each other. Consumers following this instruction and importing lower-level components or hooks from `@proyecto-viviana/ui` will encounter import resolution failures.

2. **Update the stale Solid 1 installation commands (`installation.tsx:130,132` in both installation pages)**:
   The install commands `npm install @proyecto-viviana/ui solid-js` and `npm install @proyecto-viviana/solid-spectrum solid-js` are STALE Solid 1 install lines. On npm today, `solid-js` resolves to Solid 1.x, which directly violates the packages' peer dependency requirement (`"solid-js": ">=2.0.0-rc.9 <3"`). Furthermore, the commands completely omit the required peer dependency `@solidjs/web` (`">=2.0.0-rc.9 <3"`). The commands should instruct users to install `solid-js@2.0.0-rc.9` and `@solidjs/web@2.0.0-rc.9`.

3. **Update the stale test count on the Solid Spectrum landing page (`solid-spectrum/index.tsx:161`)**:
   The claim of `"3,680 tests"` is an outdated snapshot that underreports current test coverage by nearly half. The repository now runs 7,417 tests across 577 test files (with 6,301 tests across the core package suite alone). The stat card should be updated to reflect the true test count (e.g., `"7,400+ tests"`).
