## Cause one — the accent fill is being painted as text

Routes 1 and 2, dark only, 16 instances, all on `.pv-register-card__status`:
the "Published · Glasselated theme", "Published · Spectrum S2" and two
"Unpublished · 1-Button study" badges.

Traced to a token in three hops:

    apps/web/src/components/theme/studio.css:278   color: var(--pv-accent-solid, #3b82f6)
    apps/web/src/components/theme/studio.css:24    --pv-accent-solid: var(--interactive-fill)
    packages/viviana-ui/src/style/glasselated-ramps.ts:286
        "interactive-fill": { light: "#0b5dc2", dark: "#0a6fef" }
    packages/viviana-ui/src/viviana-tokens.css:265,284   --blue-600 / --blue-700: #0a6fef

`glasselated-ramps.ts:29` already records a ratio for this token — "6.25:1 /
4.63:1 **under white**". That is the number for a fill. `studio.css:278` paints
it as ink on `--surface-raised`, which computes to `#202630` in dark, and there
it is 3.28:1. The token was verified in one ground and used in another.

Not a landing-page defect and must not be fixed on the landing page —
`--pv-accent-solid` is read at `studio.css:278`, `:602` and `:637`. This is the
case the standing memory `docs-contrast-failures-are-token-level` describes.

## Cause two — the error boundary is itself below AA

Routes 4, 5 and 6 are not measuring their own pages. They are measuring
`apps/web/src/routes/__root.tsx`:

    :83   <p style={{ color: "#9ca3af", ... }}>{props.error.message}</p>   → 2.34:1
    :88   background: "#3b82f6", white text                               → 3.67:1

Those three routes throw. In `site-gate-2026-09-21.routes.md` the first two are
Class B and the third is Class A. So the spec walked the fallback, and the
fallback is unreadable — the surface shown to a user whose page just broke.

Fixing #545 removes these three from this tally and leaves the boundary exactly
as inaccessible for the next thing that throws. Both need doing, and they are
independent.
