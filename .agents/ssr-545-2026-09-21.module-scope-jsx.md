# #545: the twenty blank routes were one line of JSX

2026-09-21, from `b22a44eb`. Every number below came from a command run in this
session; the 22/153 baseline is quoted from `.agents/site-gate-2026-09-21.routes.md`
and was not re-measured before the fix.

## What was wrong

Both copies of `ContextualHelpTrigger` built their icons at module scope:

```tsx
const helpIcon = (
  <svg width="16" height="16" viewBox="0 0 16 16" aria-hidden="true">…</svg>
);
```

JSX is a value, so that line runs when the module is evaluated. Compiled for the
server it becomes `var _v$ = ssrHydrationKey(); var helpIcon = ssr(_tmpl$, _v$)`,
and `ssrHydrationKey()` → `getHydrationKey()` is inert only while
`sharedConfig.context` is unset. `renderToString` sets that context and never
clears it. So the first page a server renders is fine, and every module
evaluated after it throws

```
getNextContextId cannot be used under non-hydrating context
```

The module then fails to evaluate, the failure propagates to the `src/menu`
barrel and to everything that re-exports it, and each route importing any of it
serves an empty shell with HTTP 200 — which is exactly the symptom the route
sweep recorded: `/theme` at 15,285 bytes against a working page's 88,026, and
`new Error("Internal Server Error")` streamed into the `$R` resolver.

Two things this explains that the earlier measurement could not. Why no test
caught it: every component test renders into a cold process. Why all 84
`/docs/components/*` routes passed while `/theme` and the `/examples*` did not:
it is not about which components a page uses, it is about whether the module was
evaluated before or after that server's first render.

In a browser the same binding is a second defect: one DOM node shared by every
instance, so a second trigger on a page steals the first one's icon.

## The fix

Each icon is a component now — `function HelpIcon(): JSX.Element` — and the call
site picks one inside `children()`. This is what upstream does: in
`@react-spectrum/s2@1.7.0` `src/Menu.tsx` the icon is rendered as
`<InfoCircleIcon …/>` inside `UnavailableIconWrapper`, never bound at module
scope. Both packages changed identically; the only divergence left between the
two files is the `triggerStyles` block the layer-boundary baseline already
records, and `vp run guard:layer-boundary` reports 524 identical / 84 diverged,
0 new forks, EXIT=0.

## The sweep

Every module-scope JSX expression in the seven published `packages/*/src` roots,
by TypeScript AST, not regex — the offending expressions are multi-line and
parenthesised, and a `.ts` file's `<T>value` is a cast, not an element. Function
bodies and default parameter values are skipped (they run per call), a
module-scope IIFE is entered (its body runs at module evaluation), and class
bodies only for `static` members.

1750 files scanned. 4 sites, all of them this defect:

```
packages/solid-spectrum/src/menu/ContextualHelpTrigger.tsx:89
packages/solid-spectrum/src/menu/ContextualHelpTrigger.tsx:103
packages/viviana-ui/src/menu/ContextualHelpTrigger.tsx:100
packages/viviana-ui/src/menu/ContextualHelpTrigger.tsx:114
```

No allowlist was needed and none was added.

## The guard

`scripts/check-idiomatic-solid.ts` already runs in Certification Gates as
`guard_idiomatic_solid` and already owns "this is not how you write Solid"
rules, so the rule went in there as its fourth check rather than into a new
script. It fails the build with each site named. `scripts/test-ci-guard-contracts.mjs`
pins it the way its neighbours are pinned: the npm script text, the workflow
step, that the scan is *called* and not merely exported, that a hit sets
`failed = true` rather than only printing, and that the scanned roots cover
every `packages/*/src` whose package.json is not private — the last one so that
publishing an eighth package cannot quietly leave it unscanned.

The regression test earns its keep only because of the warm render: the first
version of it passed on the pre-fix source and was worthless. It now calls
`renderToString(() => <span>…</span>)` before a *dynamic* import, which is the
server process the bug needs — one page served, then the next route's chunk
evaluated. A static import would hoist above the render and stay inert.

solid-spectrum `ContextualHelpTrigger.test.tsx` 16 passed and `Menu.test.tsx`
32 passed, viviana-ui `Overlays.float.test.ts` 9 passed.
