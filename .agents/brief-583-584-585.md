of the 21, but it is an unexplained divergence in the same seven lines. Mirror
upstream or write down why not.

## 2. #583 — the reduced-motion rule we invented, 2 rows

`packages/solid-spectrum/src/button/s2-action-button-styles.ts:112-113` and
`s2-button-styles.ts:57-58` both carry

    transition: { default: "default", "@media (prefers-reduced-motion: reduce)": "none" }

Upstream has no media branch at all: `ActionButton.tsx:141` and `Button.tsx:116`
are a plain `transition: 'default',`. Deleting the branch is the fix.

Do not touch the other four sites. `disclosure/index.tsx:358`,
`tabs/index.tsx:389`, `segmentedcontrol/index.tsx:165`, `skeleton/index.tsx:95`
and `toast/index.tsx:871` all match upstream exactly. S2 applies the pattern to
moving indicators and chevrons, never to a control surface. Someone carried it
one element too far; that is the whole bug.

## 3. #584 — the picker trigger's state attributes, 2 rows

`packages/solidaria-components/src/Select.tsx`, and the file already contains
the right idiom forty lines below the wrong one.

- `:776-782` builds the root props with raw booleans,
  `"data-focused": isFocused() || undefined`. Spread onto an element that
  writes `""`; React writes `"true"`. Route them through `dataAttr`
  (`utils.tsx:442`, typed `"true" | undefined`), which `:943-947` already does.
- `:943-947` renders `data-open` on the trigger button. RAC renders it on the
  root only — `react-aria-components/src/Select.tsx:284` is the single
  `data-open` in that file. Drop ours.
- `data-focused` survives on the trigger after the popover takes focus, and
  upstream's does not. That one is a focus-tracking question, not an attribute
  question: do not fix it by deleting the attribute, consumers style on it.
