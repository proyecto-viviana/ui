## Geometry contract

From `calculatePosition.ts` for **`bottom start`** after LTR translation (`translateRTL`: `'start'` → `'left'`, so placement input is `'bottom left'`). Defaults that Select/ComboBox actually use are noted; `calculatePosition.test.ts` uses `padding: 50` and is **not** the runtime default.

### Parse (`parsePlacement`, lines 247–263)

`'bottom left'` → `{placement:'bottom', crossPlacement:'left', axis:'top', crossAxis:'left', size:'height', crossSize:'width'}`.

RTL (`useOverlayPosition.ts` 434–438): `'bottom start'` → `'bottom right'` (`start`→`right`, `end`→`left`).

### Target offset (`calculatePosition`, 664–678)

If the overlay's containing block is the viewport (`offsetParent` walk ends at `documentElement`, `getContainingBlock` 806–836):

```
childOffset.top  = triggerRect.top  + documentElement.scrollTop  - documentElement.clientTop
childOffset.left = triggerRect.left + documentElement.scrollLeft - documentElement.clientLeft
childOffset.width  = triggerRect.width
childOffset.height = triggerRect.height
```

`triggerRect` is `getTargetRect?.(target)` if provided, else `node.getBoundingClientRect()`. Overlay size uses `offsetWidth`/`offsetHeight` when `ignoreScale` (not affected by CSS scale). Overlay margins from `getComputedStyle` are added into `overlaySize`.

If the containing block is a positioned ancestor, `getPosition` subtracts the parent's document offset + border − scroll, then subtracts the trigger's own margin.

### Initial `computePosition` for `'bottom left'` (266–319)

Cross axis (`left`): `crossPlacement === crossAxis` (`'left'`), so overlay left matches trigger left, then `+ crossOffset`, then clamped so the arrow stays overlapping the trigger:

```
minLeft = childOffset.left - overlaySize.width + arrowSize + arrowBoundaryOffset
maxLeft = childOffset.left + childOffset.width - arrowSize - arrowBoundaryOffset
left    = clamp(childOffset.left + crossOffset, minLeft, maxLeft)
```

Main axis (`placement !== axis` because `'bottom' !== 'top'`):

```
top = Math.floor(childOffset.top + childOffset.height + offset)
```

(`bottom` is not set.) `offset` default in `useOverlayPosition` is `0`; RAC `Popover` default is `8` (`Popover.tsx:239`); S2 ComboBox/Picker pass size-based `menuOffset` (6/6/7/8) and `hideArrow` so S2 does **not** add the extra `+8` arrow gap (`S2 Popover.tsx:241`: `offset={(props.offset ?? 8) + (hideArrow ? 0 : 8)}`).

### Flip (`shouldFlip` default `true`, 465–501)

Available space **below** the trigger (`getAvailableSpace` for `placement !== axis`):

```
spaceBelow = max(0,
  boundary.height + boundary.top
  + (isContainerDescendentOfBoundary ? containerOffsetWithBoundary.top : 0)
  - childOffset.top - childOffset.height
  + container.scroll.top
  - margins.top - margins.bottom
  - padding - offset)
```

Flip if `overlaySize.height > spaceBelow` **and** the flipped (top) available space is **strictly greater**. After flip, `placement` becomes `'top'` and position uses `bottom` instead of `top`:

```
containerHeight = isContainerPositioned ? container.height : container.totalHeight
bottom = Math.floor(containerHeight - childOffset.top + offset)
```

`data-placement` / RAC render-prop `placement` is the **primary axis only** after flip (`'top'|'bottom'|'left'|'right'`), never `'bottom start'`. Test: RAC Popover `should support render props` expects text `'Popover at bottom'` for `placement="bottom start"`.

### Cross-axis delta (`getDelta`, 181–234) then `maxHeight`

`left += getDelta(...)` to keep the overlay inside `[boundaryStart+padding, boundaryEnd-padding]`.

`heightGrowthDirection` for bottom placement is `'bottom'` (504–510). Then:

```
overlayTop = position.top - container.scroll.top     // bottom-placement case
boundingRect.top    = max(boundary.top + transform, (visualViewport.offsetTop ?? boundary.top) + transform)
boundingRect.bottom = min(boundary.top + boundary.height + transform,
                          (visualViewport.offsetTop ?? 0) + (visualViewport.height ?? 0))
maxHeight = max(0, boundingRect.bottom - overlayTop - (margins.top + margins.bottom + padding))
```

If caller `maxHeight` is set and smaller, it wins (`544–546`). Then `overlaySize.height = min(overlaySize.height, maxHeight)` and `computePosition` + `getDelta` **run again**.

`containerPadding` default **12** (`useOverlayPosition.ts:189`). S2 popover CSS `maxWidth: 'calc(100vw - 24px)'` is `2 * 12`.

### Runtime style application (`useOverlayPosition.ts:236–322, 400–409`)

**Before first successful `calculatePosition`:**

```
style = { position: 'fixed', top: 0, left: 0, zIndex: 100000, maxHeight: '100vh' }
placement = null
triggerAnchorPoint = null
```

This is the “appears somewhere else” window: overlay is at the **viewport origin** until `updatePosition` writes pixel `top`/`left`.

**On each `updatePosition` (when `!maxHeight` user prop):** overlay is temporarily forced to `top:0px; bottom:''; maxHeight: visualViewport.height || innerHeight` so a second-render RAC collection can measure, then styles are written immediately on the DOM (not waiting for React):

```
overlay.style.top/bottom/left/right = '' then each position key + 'px'
overlay.style.maxHeight = position.maxHeight != null ? position.maxHeight + 'px' : ''
```

React state then stores `position` for arrow / `data-placement` / `--trigger-anchor-point`.

**After position exists:**

```
style = { position: 'absolute', zIndex: 100000, ...position.position, maxHeight: position.maxHeight }
```

S2 sets `zIndex: undefined` and uses `isolation: 'isolate'` instead (`S2 Popover.tsx:154, 243–246`).

### `--trigger-width` / `--trigger-anchor-point` `[RAC]`

`--trigger-anchor-point`: `"${x}px ${y}px"` from `triggerAnchorPoint` (`Popover.tsx:327–328`). Origin is arrow center if `arrowSize > 0`, else the start/center/end of the trigger edge (`calculatePosition.ts:616–631`).

`--trigger-width`: RAC Popover measures `triggerRef.getBoundingClientRect().width + 'px'` on layout and `ResizeObserver`, unless `renderProps.style['--trigger-width']` is already set (`Popover.tsx:309–331`). ComboBox context pre-sets it from input+button union if no Group (`ComboBox.tsx:247–263, 340`). S2 ComboBox overrides only when `menuWidth` is passed; S2 Picker sets `width: ${menuWidth}px` when `menuWidth && !isQuiet`.

## Entering / exiting

**At this pin, `useEnterAnimation` / `useExitAnimation` live in `react-aria/src/utils/animation.ts` (RAC `Popover.tsx:55` imports `react-aria/private/utils/animation`). They are not in RAC `utils.tsx`. There is no `getAnimationDuration`, no `animationend`/`transitionend` listeners, and no rAF-duration fallback.** Completion is `element.getAnimations()` → `Promise.allSettled(a.finished)` then `flushSync(onEnd)`. JSDOM / no `getAnimations` / `animations.length===0` → **synchronous** `onEnd`.

### Reopen-before-exit-finished (verbatim)

`useExitAnimation` (`animation.ts:48-80`):

```
exitState ∈ {'closed','open','exiting'}
if exitState==='open' && !isOpen → setExitState('exiting')
if exitState is 'closed' or 'exiting' && isOpen → setExitState('open')   // interrupt
isExiting = (exitState === 'exiting')
on animation end: setExitState(s => s==='exiting' ? 'closed' : s)
```

RAC `Popover.tsx:173-196`: `isExiting = props.isExiting || (!shouldSkipAnimation && exitAnimation)`. **If `!state.isOpen && !isExiting` the component returns `null` (unmount).** While `isExiting`, the DOM **stays mounted** with `data-exiting`.

If the user reopens **before** `getAnimations().finished` for the exit:

1. `isOpen` becomes true while `exitState==='exiting'` → immediately `exitState='open'`, `isExiting=false`, `data-exiting` removed.
2. The cleanup of `useAnimation` sets `canceled=true`, so the pending exit `onEnd` **does not** unmount.
3. `useEnterAnimation` does **not** reset: its `useState(true)` only runs on first mount. After the first enter, `isEntering` is already `false`. The still-mounted popover therefore **skips a second enter animation**.
4. S2: `isEntering`/`isExiting` both false → `opacity` not forced to 0; `pointerEvents` not `none`.

**Stuck-transparent mechanisms (owner defect):**

1. **`isEntering` stuck true** (`animation.ts:21-45`): `useEnterAnimation` returns `isEntering && isReady`. RAC passes `isReady=!!placement` (`Popover.tsx:251`). S2 `opacity: {isEntering:0, isExiting:0}` (`s2/Popover.tsx:119-122`). If `getAnimations()` returns a transition/animation whose `.finished` never settles, `data-entering` remains and **opacity stays 0**.
2. **`isExiting` stuck true**: same wait; S2 also sets `pointerEvents: {isExiting:'none'}` (`155-157`) so the list is transparent **and** unclickable, still mounted.
3. **Pre-position flash** (`useOverlayPosition.ts:400-405`): until placement exists, overlay is `position:fixed; top:0; left:0`. RAC `isEntering` is **false** until `placement` is truthy (`isReady`). First paint can show a fully opaque popover at the **viewport origin**, then jump. After placement, `isEntering` becomes true → S2 opacity 0 → then `useLayoutEffect` **cancels CSSTransitions** (`animation.ts:30-38`) so the fade-in starts only when `isEntering` clears.
4. **Re-open after unmount**: new mount resets `isEntering=true`. If placement is delayed, see (3). If animations never finish, see (1).

## Selection & keyboard

`navigateToKey`: `setFocusedKey`; if `shift`+multiple → `extendSelection`; else if `selectOnFocus` and not non-contiguous modifier → `replaceSelection`. `selectOnFocus` default `manager.selectionBehavior === 'replace'` (`161`).

Non-contiguous modifier: Mac **Alt**, Windows **Control** (`isNonContiguousSelectionModifier`).
